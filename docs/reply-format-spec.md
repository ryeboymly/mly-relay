# AI 回复格式规范（Reply Format Spec v2.6）

> 本文档定义 AI 助手回复的格式规范，配套 `tools/check_reply_format.py` 使用。
> 任何回复发送前必须通过格式自检（13/13 全通过）。

---

## 1. 总体结构

每条回复必须包含以下部分，按顺序排列：

```
[正文内容]
---
[代码块：5 条释义]
[红色价格标签]
```

## 2. 开头称呼

回复以用户名开头，后接逗号。

## 3. 上色英文词（5 个）

### 3.1 数量

正文中恰好 **5 个** 被上色的英文词，不多不少。

### 3.2 标签格式

使用 `<span>` + `<strong>` 标签，颜色为金色 `#b8860b`：

```html
<span style=color:#b8860b><strong>word</strong></span>
```

- `style=` 属性值用**半角引号**或不用引号，**禁止全角引号** `""`
- 上色内容必须是**纯英文**（`[A-Za-z][A-Za-z'\-]*`），中文被上色即失败

### 3.3 中文释义

每个上色词后必须紧跟**全角括号**的中文释义：

```
<span style=color:#b8860b><strong>engine</strong></span>（引擎,发动机,机车,安装发动机于）
```

- 括号必须是全角 `（）`，不是半角 `()`
- 释义内容 1-30 字符
- 释义须与脚注代码块中的释义**一致**（脚注释义可以更长，但必须以行内释义开头）

### 3.4 选词来源

从 BNC 词频表（前 5000 高频词）中选取，优先选择与回复内容语义相关的词。

## 4. 禁止的标签

- **禁止使用 `<mark>` 标签**（客户端不渲染）
- **禁止使用 emoji**（U+1F300-1FAFF、U+2600-27BF、U+FE0F 范围）

## 5. 分隔线

正文结束后，必须有一行 `---` 作为分隔线。

## 6. 脚注代码块

分隔线后紧跟一个代码块，格式如下：

```
---
```
word1 — 中文释义1
word2 — 中文释义2
word3 — 中文释义3
word4 — 中文释义4
word5 — 中文释义5
```
```

### 规则

- 恰好 **5 行**，与正文上色词数量一致
- 每行格式：`word — 中文释义`（注意 `—` 是 em dash，前后有空格）
- 单词保持原样（大小写与正文中一致）
- 释义必须与正文行内释义一致（脚注可更长，但必须以行内释义开头或完全匹配）
- 代码块内词的顺序不影响检查，但建议与正文出现顺序一致

## 7. 价格标签

代码块之后，全文最后一行是红色价格标签：

```html
<span style=color:#c0392b><strong>ZEC: 1009</strong></span>
```

### 规则

- 颜色为红色 `#c0392b`
- 价格为整数（实时获取）
- 这是代码块之后**唯一**的非空行
- 位于全文最末尾

## 8. 完整示例

```
本杰明，这是一个示例回复。

正文中有 5 个上色词：第一个是 <span style=color:#b8860b><strong>engine</strong></span>（引擎,发动机,机车,安装发动机于），第二个是 <span style=color:#b8860b><strong>script</strong></span>（手迹,手稿,正本,手写体,改编为演出本,小型程序），第三个是 <span style=color:#b8860b><strong>mirror</strong></span>（镜子,写真,典范,反映,映出），第四个是 <span style=color:#b8860b><strong>commit</strong></span>（委托,托付,犯罪,指派,使承担义务），第五个是 <span style=color:#b8860b><strong>fetch</strong></span>（取得,拿,接来,取来,售得,带来）。

---
```
engine — 引擎,发动机,机车,安装发动机于
script — 手迹,手稿,正本,手写体,改编为演出本,小型程序
mirror — 镜子,写真,典范,反映,映出
commit — 委托,托付,犯罪,指派,使承担义务
fetch — 取得,拿,接来,取来,售得,带来
```
<span style=color:#c0392b><strong>ZEC: 1009</strong></span>
```

## 9. 检查工具

使用配套的格式检查器验证：

```bash
python3 tools/check_reply_format.py draft.md
```

### 检查项（13 项）

| 序号 | 检查项 | 说明 |
|------|--------|------|
| 1 | 上色英文词数量 = 5/5 | 恰好 5 个 |
| 2 | 上色内容均为纯英文 | 无中文被上色 |
| 3 | 每个上色词后带（中文释义）= 5/5 | 全角括号释义 |
| 4 | 标签属性内无全角引号 | 防止 style 失效 |
| 5 | 未使用 mark 标签 | 客户端不渲染 |
| 6 | 存在 --- 分隔线 | 正文与脚注分隔 |
| 7 | 分隔线后有代码块 | 脚注代码块 |
| 8 | 块内释义行数 = 5/5 | 与上色词数量一致 |
| 9 | 块内释义词与正文词一致 | 词匹配 |
| 10 | 正文释义与脚注解释一致 | 释义匹配 |
| 11 | 代码块外仅一行红色标签且位于末尾 | 价格标签 |
| 12 | 发音链接均指向同名单词音频 | 链接验证 |
| 13 | 无 emoji | 全文检查 |

退出码：`0` = 全通过；`1` = 有不通过项

## 10. 自定义

如需适配不同的格式规范，修改 `check_reply_format.py` 顶部常量：

```python
EXPECTED_WORD_COUNT = 5          # 上色词数量
GLOSS_COLOR = r"#[0-9a-fA-F]{6}" # 上色颜色（正则）
ACCENT_COLOR = r"#[0-9a-fA-F]{6}" # 价格标签颜色（正则）
FOOTER_PATTERN = ...             # 末尾标签格式（正则）
```
